# Зависимости: нет внешних зависимостей.

# Скилл: secret-hygiene

Запускается командой `/secret-hygiene`. Проводит аудит текущего проекта на предмет утёкших секретов и проблем с их хранением.

## Что проверять

### 1. Паттерны секретов в файлах проекта

Ищи через Grep по следующим паттернам (кроме node_modules/, .venv/, .gradle/, __pycache__/):

```
password\s*=\s*[^\$\{]          # password = "что-то" (не плейсхолдер)
passwd\s*=\s*[^\$\{]
pwd\s*=\s*[^\$\{]
secret\s*=\s*[^\$\{]
token\s*=\s*[^\$\{]
api_key\s*=\s*[^\$\{]
apikey\s*=\s*[^\$\{]
-----BEGIN (RSA|EC|OPENSSH|PGP)  # приватные ключи
Authorization:\s*Bearer\s+[A-Za-z0-9]  # токены в коде
```

Игнорировать: строки в `# комментариях` со словом "example"/"пример", строки в `*.md` с `***` (уже замаскированы).

### 2. Проверка .gitignore

Убедись что в `.gitignore` (или глобальном `~/.gitignore`) есть:
```
.env
.env.*
*.env
!.env.example
```

Если `.env` существует в проекте, но не в `.gitignore` — это критическая проблема.

### 3. Проверка git-истории

```powershell
# Ищем упоминания паролей в коммитах (только сообщения — быстро)
git log --all --oneline | Select-String -Pattern "password|secret|token|credential" -CaseSensitive:$false

# Ищем секреты в содержимом диффов (медленнее, запускать по запросу)
git log --all -p --follow -- "*.env" "*.config" "*.yaml" | Select-String "password|secret|token"
```

### 4. Проверка документации

Ищи секреты в `.md`, `.docx`, `.txt` файлах в `doc/`, `docs/`, корне проекта.

## Формат отчёта

После проверки выдать структурированный отчёт:

```
## Аудит секретов — [название проекта]

### Критично (требует немедленного действия)
- [файл:строка] — описание проблемы

### Предупреждения (исправить желательно)
- [что] — [почему это риск]

### Проверено, всё ок
- .gitignore: содержит .env ✓
- Открытых паролей в коде: не найдено ✓

### Рекомендации
- [конкретный шаг]
```

## Что делать при находке

1. **Пароль/токен в коде (не в git)** — предложить заменить на `os.environ.get("VAR_NAME")` + добавить в `.env`.
2. **`.env` не в `.gitignore`** — немедленно добавить, проверить не попал ли уже в git: `git ls-files .env`.
3. **Секрет в git-истории** — предупредить: секрет нужно сменить (не "вычистить из истории" как первый шаг, а именно сменить — он уже мог быть скопирован). Предложить `git filter-repo` / BFG только если пользователь подтвердит и понимает что это перепишет историю.
4. **Пароль в документации** — найти и заменить на `***` или `<пароль>`, сохранить в реальный `.env`.

## Gotchas

- Не паниковать при находке паттерна `password = ""` или `password = None` — это не секрет.
- Паттерны в тестах с `test_password = "testpass"` — низкий риск, но отмечать.
- Переменные окружения вида `$env:PASS` или `${PASS}` — это уже правильный паттерн, не находка.
- Не читать бинарные файлы (`.docx`, `.xlsx`, `.pdf`) через Grep — только через специализированные инструменты или doc-specialist.
