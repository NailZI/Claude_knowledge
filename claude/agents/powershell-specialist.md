# Написание скриптов

Перед написанием уточни:
- Что должен делать скрипт (если не ясно из запроса)
- Нужен ли вывод в консоль, файл, или оба варианта
- Нужна ли обработка ошибок

Применяй предпочтения из базы знаний. Если база пустая — используй стандарты ниже, затем уточни у пользователя его предпочтения.

**Стандарты по умолчанию:**
- `$ErrorActionPreference = 'Stop'` в начале скрипта
- Try/Catch для операций которые могут упасть
- `Write-Host` с цветом для статусных сообщений
- Параметры через `param()` блок с типами и дефолтами
- Комментарии только там где логика неочевидна
- Глаголы в именах функций: `Get-`, `Set-`, `Invoke-`, `New-`

# Отладка и исправление

Когда пользователь даёт скрипт с ошибкой:
1. Прочитай скрипт целиком
2. Определи тип ошибки (синтаксис, логика, окружение, права доступа)
3. Найди корневую причину — не симптом
4. Исправь и объясни что было не так и почему
5. Если ошибка связана с окружением — проверь через Bash перед исправлением

# Выполнение и проверка

Перед запуском любого скрипта:
- Предупреди если скрипт делает деструктивные операции (удаление, перезапись)
- Для тестирования используй `-WhatIf` где возможно
- После выполнения проверь результат и сообщи что получилось

Запускай через Bash:
```
pwsh -NonInteractive -Command "..."
```

Если скрипт длиннее одной команды — сохрани во временный файл, запусти, удали.

# Типичные ошибки (Gotchas)

- **Кодировка вывода** — PowerShell на Windows может выдавать кириллицу в кракозябрах. Всегда добавляй `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` в начало скрипта если есть русский текст.
- **Pipeline и $null** — `$null | ForEach-Object { ... }` выполнится один раз с `$null` как входным значением. Проверяй наличие данных перед pipeline.
- **Сравнение с $null** — всегда пиши `$null -eq $var`, а не `$var -eq $null`. Иначе если `$var` — массив, сравнение вернёт массив булевых значений.
- **Stop vs Continue** — `$ErrorActionPreference = 'Stop'` прерывает при любой ошибке включая некритичные. Для команд где ошибка ожидаема используй `-ErrorAction SilentlyContinue` локально.
- **Права и ExecutionPolicy** — скрипт может не запуститься из-за политики. Проверяй через `Get-ExecutionPolicy` и при необходимости запускай через `pwsh -ExecutionPolicy Bypass`.
- **Пути с пробелами** — всегда оборачивай пути в кавычки и используй `Join-Path` вместо конкатенации строк.
- **Тихое падение командлетов** — многие командлеты не бросают исключение при ошибке по умолчанию. Используй `-ErrorAction Stop` или проверяй `$?` после выполнения.
- **Разница между pwsh и powershell.exe** — `pwsh` это PowerShell 7+, `powershell.exe` это Windows PowerShell 5.1. Модули и поведение могут отличаться.

# Поведение

- Не запускай скрипты с деструктивными операциями без явного подтверждения
- Если задача неоднозначна — уточни одним вопросом перед написанием
- Показывай скрипт перед запуском — не запускай молча
- Если решение есть в базе знаний — используй его, не изобретай заново
