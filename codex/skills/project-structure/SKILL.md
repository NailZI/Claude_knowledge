# Project Structure

## Роль

Действуй как хранитель структуры проекта. Твоя задача — размещать файлы предсказуемо, не создавать лишние каталоги и сохранять уже существующие соглашения репозитория.

## Базовый принцип

Если проект уже имеет свою структуру, следуй ей. Не навязывай новый шаблон поверх существующего репозитория.

Если проект новый или почти пустой, используй простой каркас ниже. Создавай папку только вместе с первым реальным файлом внутри неё.

## Размещение файлов по умолчанию

- Точка входа или основной исполняемый файл: корень проекта.
- Исходный код, модули, классы, библиотеки: `src/`
- Тесты: `tests/`
- Документация, кроме главного `README.md`: `docs/`
- Конфигурация: `config/`
- Входные данные и примеры данных: `data/`
- Результаты работы, артефакты, отчёты: `results/`
- Логи: `logs/`
- Временные файлы, отладочные артефакты: `tmp/`
- Статические ресурсы: `assets/`

## Что держать в корне

- `README.md`
- `.gitignore`
- один или несколько файлов запуска только если это реально основной вход
- манифесты и менеджеры зависимостей, характерные для стека: `package.json`, `pyproject.toml`, `requirements.txt`, `Cargo.toml`
- локальные проектные инструкции, если они нужны: `AGENTS.md`

Не поднимай в корень рабочие данные, временные выгрузки, логи и вспомогательные документы.

## Правила принятия решения

Перед созданием файла:

1. Определи, это код, документ, конфиг, данные, результат или временный файл.
2. Проверь, есть ли в проекте уже принятая папка для такого типа файлов.
3. Если соглашение уже есть, продолжай его.
4. Если проекта почти нет, используй размещение по умолчанию из этого skill.
5. Если файл неочевиден по назначению, спроси пользователя.

## Минимальные правила для нового проекта

- Не создавай пустые папки без нужды.
- Не создавай больше файлов, чем нужно для первого рабочего шага.
- Добавляй в `.gitignore` как минимум `tmp/`, `logs/`, `results/`, `.env`, кеши языка и системный мусор.
- Если стек проекта диктует другой стандарт, следуй ему вместо этого skill.

## Когда не использовать

- Не используй этот skill, чтобы ломать существующую зрелую структуру проекта.
- Не используй его как оправдание для массового рефакторинга каталогов без запроса пользователя.
