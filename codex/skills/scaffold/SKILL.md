# Scaffold

## Роль

Действуй как генератор минимального каркаса проекта. Создавай только то, что действительно нужно для старта, и не превращай bootstrap в генерацию десятков пустых файлов.

## Принципы

- Сначала выясни минимум вводных, которые реально влияют на структуру.
- До создания покажи дерево файлов и дождись подтверждения.
- После подтверждения создай только базовые рабочие файлы.
- Уважай существующее содержимое каталога и не перезаписывай важные файлы без явного согласия.

## Что уточнять

- Тип проекта, если он неясен: библиотека, CLI, скрипт, сервис, документационный проект, другое.
- Куда создавать: текущая папка или новая подпапка.
- Нужен ли git-репозиторий и `.gitignore`.
- Нужен ли проектный `AGENTS.md` с локальными правилами. Если глобальных правил достаточно, не создавай его.

## Порядок работы

### 1. Уточнение

Если контекст уже ясен, не задавай лишних вопросов. Если нет, задай 1-3 самых важных.

### 2. План создания

Покажи дерево того, что будет создано. Используй только реальные файлы первого дня. Не добавляй каталоги ради красоты.

### 3. Создание

После подтверждения создай файлы с минимальным, но осмысленным содержимым. Пустые файлы допустимы только когда формат или инструмент этого требует, и это действительно полезно.

### 4. Завершение

Коротко перечисли созданное и укажи следующий полезный шаг.

## Шаблоны по умолчанию

### Общий проект

```text
project/
  README.md
  .gitignore
  src/
```

### Python-скрипт или утилита

```text
project/
  README.md
  .gitignore
  requirements.txt
  src/
    main.py
```

### PowerShell-скрипт

```text
project/
  README.md
  .gitignore
  src/
    main.ps1
```

### Документационный проект

```text
project/
  README.md
  docs/
    index.md
```

## Минимальное содержимое базовых файлов

### `README.md`

- Название проекта
- 1-2 предложения о назначении
- Как запустить или с чего начать

### `.gitignore`

Включай только релевантное для стека, но почти всегда добавляй:

```text
tmp/
logs/
results/
.env
```

### Точка входа

Создавай короткий, рабочий стартовый файл, а не заглушку из одного комментария.

## Чего не делать

- Не создавай `CLAUDE.md` и другую Claude-специфичную обвязку.
- Не создавай десятки пустых директорий и `.gitkeep`, если пользователь не просил.
- Не генерируй локальный `AGENTS.md` без необходимости.
- Не показывай план после создания; сначала план, потом подтверждение, потом файлы.
