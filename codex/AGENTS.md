# Общие правила работы

## Язык

- Общайся со мной на русском языке.
- Имена переменных, функций и классов пиши на английском.
- Комментарии в коде пиши на русском, если проект не требует иного.

## Порядок работы

- Перед существенными изменениями изучи структуру проекта.
- Для сложных задач сначала составь краткий план.
- Не изменяй файлы, не относящиеся к задаче.
- Не устанавливай новые зависимости без обоснования.
- Не выполняй commit, push, merge и публикацию без прямого указания.

## Проверка результата

- После изменений запускай доступные тесты.
- Проверяй lint, форматирование и статический анализ.
- В итоговом сообщении перечисляй:
  - изменённые файлы;
  - выполненные проверки;
  - известные ограничения;
  - невыполненные проверки.

## Безопасность

- Не выводи токены, пароли и содержимое файлов `.env`.
- Не удаляй пользовательские данные.
- Не выполняй разрушительные команды без подтверждения.

## Большие задачи

- Если задача большая, обособленная и повторяемая, сначала быстро уточни цель, границы и ожидаемый результат.
- После этого предложи создать локальный skill или отдельный набор правил для этой задачи.
- Не создавай новый skill автоматически без запроса пользователя.

## Новые файлы

- Для каждого нового файла, где синтаксис допускает комментарий в начале, добавляй короткий хедер с пунктами:
  - назначение файла;
  - взаимодействие с другими файлами или модулями;
  - важные параметры или зависимости;
  - `Created` и `Modified`.
- Если в файле уже есть шапка, дополняй её, а не дублируй.

## Секреты

- Никогда не проси пользователя вставить пароль, токен или ключ прямо в чат.
- Если секрет всё же показан, замаскируй его в ответе и предложи заменить.
- Ссылайся на источник секрета, а не на его значение: переменная окружения, `.env`, секрет-хранилище, Credential Manager.
- Для новых проектов проверяй, что `.env` и похожие файлы исключены через `.gitignore`.
